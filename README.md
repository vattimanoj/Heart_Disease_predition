## Overview

This project trains a **Gaussian Naive Bayes** classifier on the UCI-style heart disease dataset (`heart.csv`) and exposes it through a small web form where a user enters seven clinical vitals and gets an instant prediction: *No Heart Disease* or *Heart Disease Detected*.

The pipeline handles:

- Loading and splitting the dataset
- Outlier handling with a Yeo-Johnson transform + IQR trimming
- Feature selection (constant, quasi-constant, and hypothesis-testing based filtering)
- Class balancing with SMOTE
- Feature scaling with `StandardScaler`
- Model comparison and final model training
- Saving the trained model/scaler for reuse in the web app

## Pipeline Details

1. **Load & split** — `heart.csv` is loaded, the last column is treated as the target, and the data is split 80/20 into train/test sets.
2. **Outlier handling** (`variable_transformation.outliers`) — every feature is Yeo-Johnson transformed and clipped to its IQR-based upper/lower bounds.
3. **Feature selection** (`feature_selection.best_col`) — drops constant columns, quasi-constant columns, and columns that fail a hypothesis test against the target.
4. **Class balancing** — `SMOTE` oversamples the minority class in the training set.
5. **Scaling** — a `StandardScaler` is fit on the balanced training data and applied to both train and test sets.
6. **Model training** — several candidate models are compared (`all_model.common`), and the final model is a `GaussianNB` classifier.
7. **Persistence** — the trained model and scaler are pickled to `model.pkl` and `scaled.pkl` for use by the Flask app.

### Final feature set

After feature selection, the model is trained on **seven features**, in this order:

| # | Feature   | Description                                   |
|---|-----------|------------------------------------------------|
| 1 | `age`     | Age in years                                    |
| 2 | `sex`     | 1 = male, 0 = female                            |
| 3 | `cp`      | Chest pain type (0–3)                           |
| 4 | `thalach` | Maximum heart rate achieved                     |
| 5 | `oldpeak` | ST depression induced by exercise, relative to rest |
| 6 | `slope`   | Slope of the peak exercise ST segment (0–2)     |
| 7 | `thal`    | Thalassemia result (1–3)                        |

> ⚠️ If your `heart.csv` uses a different encoding for `cp`, `slope`, or `thal`, update the option values in `templates/index.html` to match.

## Getting Started

### Prerequisites

- Python 3.9+
- pip

### Installation

```bash
git clone <your-repo-url>
cd <your-repo-folder>
pip install -r requirements.txt
```

**requirements.txt**
```
flask
pandas
numpy
scikit-learn
imbalanced-learn
scipy
seaborn
matplotlib
gunicorn
```

### Train the model

Place `heart.csv` in the project root, then run:

```bash
python main.py
```

This runs the full pipeline and produces `model.pkl` and `scaled.pkl` in the project root.

### Run the web app

```bash
python app.py
```

Then open **http://127.0.0.1:5000** in your browser, fill in the seven vitals, and submit to get a prediction.

## Deployment (Render)

This app is set up to deploy on [Render](https://render.com) as a **Web Service**.

1. **Push your repo to GitHub**, including `app.py`, `templates/index.html`, `requirements.txt`, `Procfile`, `model.pkl`, and `scaled.pkl`.
   > `model.pkl` and `scaled.pkl` must be committed (or generated at build time — see note below), since Render doesn't have `heart.csv` unless you add it.
2. On Render, click **New +** → **Web Service** and connect your GitHub repo.
3. Configure the service:
   | Setting | Value |
   |---|---|
   | Environment | Python 3 |
   | Build Command | `pip install -r requirements.txt` |
   | Start Command | `gunicorn app:app` |
4. Render automatically sets a `PORT` environment variable — `app.py` already reads it (`os.environ.get("PORT", 5000")`) and binds to `0.0.0.0`, so no extra config is needed.
5. Click **Create Web Service**. Render will build and deploy; once live, your app will be reachable at `https://<your-service-name>.onrender.com`.

**Regenerating the model on Render instead of committing the pickles:** if you'd rather not commit `model.pkl`/`scaled.pkl`, add `heart.csv` to the repo and change the Build Command to:
```
pip install -r requirements.txt && python main.py
```
This retrains the model during every build and produces fresh pickle files before the app starts.
